1. Address Translation Math (Phase 3):

Given:
PAGE_SIZE = 4096 bytes
Logical Address = 10000

Page Number = Logical Address // PAGE_SIZE
            = 10000 // 4096
            = 2

Offset = Logical Address % PAGE_SIZE
       = 10000 % 4096
       = 1808

Therefore:
- Page Number: 2
- Offset: 1808


2. Physical Memory Fragmentation:

The Operating System does not need to store continuous logical pages in continuous physical memory frames. In the page table simulation, Page 0 was stored in Frame 12 while Page 1 was stored in Frame 45.

This happens because physical RAM may already be fragmented or partly used by other processes. Paging allows the OS to place each page into any available physical frame instead of requiring one large continuous block of free memory. The Page Table keeps track of which physical frame contains each logical page.

This helps the Operating System use available RAM more efficiently and solves the problem of physical memory fragmentation.


3. The AI Context (mmap):

In the mmap experiment, the program created a 50MB model file, but the physical RAM usage increased only from 13.87 MB to 13.88 MB after the file was mapped.

This happens because mmap maps the file into the process's Virtual Memory instead of loading the entire file into Physical RAM at once. The OS uses the Page Table to connect virtual addresses to the file on disk.

When the program accesses index 25,000,000, the OS loads only the required page into a physical RAM frame if that page is not already in memory. After the required page is available, the program continues and reads the value successfully.

This allows large AI model files to be accessed without loading the whole model into RAM at the same time.
